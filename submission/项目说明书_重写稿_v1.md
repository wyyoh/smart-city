# 数智选材——AI驱动的道路养护决策与沥青材料方案智能推荐系统
## 项目说明书重写稿 v1

赛事：第十二届中国研究生智慧城市技术与创意设计大赛企业揭榜课题一  
企业：海韵（海南）材料科技有限公司

### 项目简介
“数智选材”面向道路养护中的沥青材料选型与配合比比选，将养护场景、性能要求、再生混合料组成、历史试验结果和候选方案组织为可追溯的决策流程。系统通过场景规则解析、材料数据关联、约束筛选、多指标比较和证据追溯，帮助使用者理解推荐理由及适用范围；同时支持配方假设的人工调整与版本比较，并探索小样本性能预测和后续验证建议，为企业材料研发及养护决策系统集成提供可复用的数据模型、规则与接口基础。

关键词：再生沥青混合料；道路养护；智能选材；可解释推荐；多目标决策

# 一、立项依据

道路养护不仅要决定“采用何种工法”，还需要回答“选用什么材料、采用何种级配与配合比、方案依据是什么”。不同场景在气候、交通荷载、结构层位和病害类型上存在差异，对高温抗车辙、低温抗裂和水稳定性等性能的关注程度也不同。材料选型若主要依赖人工查阅分散的试验表格和经验判断，容易出现资料检索耗时、方案难以同口径比较、单项性能与综合需求脱节等问题。

再生沥青混合料的选型更为复杂。性能不仅与沥青标号有关，还受到新集料与RAP组成、各档材料比例、级配、油石比、沥青产品系列及具体配方等因素影响。相同标号可能对应不同配方；同一名义RAP掺量也不能完整表达旧沥青的实际参与状态。若仅按标号或单一指标排序，容易忽略材料身份、试验条件和多性能之间的权衡。

现有规范、企业经验、历史试验和专业软件各有价值，但场景条件仍需人工转换为性能指标和优先级；原料、级配、配方、试件和性能数据分散，缺测及重复试件会影响比较；单一评分难以说明关键约束冲突，配方调整后也不易追踪哪些证据仍适用。本项目据此构建“场景需求—材料证据—约束筛选—多方案比较—调整与验证”的辅助决策流程，不替代工程师作出最终工程批准，而是让候选方案更容易筛选、比较、解释和复核。

企业提供的《再生沥青混合料实验数据表》包含原料筛分与密度、级配、体积指标、浸水马歇尔、冻融劈裂、高温车辙、低温弯曲及沥青指标。数据复核识别出68个“来源＋完整级配标识”方案块和2,052条性能明细；明细行数不等于独立配方或批次数量。多数记录可按来源与完整级配名称关联；疑似汇总行、跨组公式、重复属性列及个别比例异常均保留原值与复核状态，不直接作为可靠训练标签。数据可支撑材料数据底座、配比核算、历史方案比较和初步模型研究。可确定计算的组成比例、合成级配与油石比换算由程序执行；缺乏依据的成本、寿命、碳排放和未披露配方信息则保留为未知。

# 二、项目创新内容

项目的创新重点不是单独采用某种算法，而是将场景要求、实验数据、约束判断、方案调整与验证行动组织为可追溯的材料决策机制。

## 2.1 场景驱动的可解释推荐
系统将气候与交通、结构层位、病害类型与程度、工法、材料约束和目标性能结构化，并转换为待检查的性能指标、优先级与适用条件。规则保留来源、版本和人工确认记录；信息不足或超出适用范围时提示补充条件，不套用默认阈值。材料侧关联原料来源、完整级配、沥青系列与局部配方标记、油石比、试验组及性能结果。推荐结果可追溯至原始工作表与单元格，让使用者理解方案为何入选、证据是否适用于当前场景，以及还需确认哪些条件。构造阈值与正式规则分开登记，避免将演示设定误写为通用规范。

## 2.2 硬约束、未知证据与多目标权衡
系统先检查必要条件，再比较满足条件的候选；缺少结果、试验方法不可比或适用条件不明时，分别标记为缺测或不可比，不自动视为满足。无可确认方案时，系统区分“证据不足”与“已知冲突”：前者表示现有记录不足以判断，后者给出当前候选范围下的失败依据，并展示哪些要求的调整可能改变筛选结果。冲突结论只对声明的候选池与规则成立，不外推为普遍材料规律。对可行候选，系统比较动稳定度、低温弯曲应变、TSR及残留稳定度比等已有指标，并允许按场景调整优先级。成本、寿命、碳排放与供货条件仅在具备同口径可靠数据时参与定量排序。

## 2.3 人机协同的配方演化
系统支持在已有方案基础上开展有限配方假设，例如调整油石比或在已披露的新集料档位间进行比例变化。每个假设保存父方案、组分变化、计算结果和数据来源，并与历史实测方案分开展示。新配方没有实测结果时，不继承父方案的性能实测值，也不将模型预测当成真实试验。调整后系统重新检查组成与级配，并提示哪些性能需要重新评估或补测。由此，推荐从一次性结果变为可审查的方案演化过程，也为后续主动试验设计预留接口。

## 2.4 AI模型定位
项目比较了均值基线、树模型、支持向量回归、高斯过程及多任务方法，并探索保守集成和分组验证。现有结果显示，各指标预测收益并不一致：部分应变预测配置相对均值基线有小幅改善，动稳定度及水稳定性指标尚未形成稳定、全面的优势。因此，模型当前用于研究与辅助比较，而非工程验收判定。比例与级配等确定关系由程序计算，工程适用性由有来源的规则约束，证据不足的判断转入人工确认或进一步验证。

# 三、实施方案

## 3.1 技术路线
**养护场景输入→需求解析与确认→材料及试验数据关联→配比与适用性检查→候选筛选与多指标比较→推荐依据展示→人工调整与验证行动。**数据管理、规则判断、性能模型和交互界面模块化实现，便于独立更新及后续系统对接。原型可本地运行，并提供结构化数据、规则配置、接口契约和可追溯决策记录。

## 3.2 数据与规则
系统保留企业原始工作簿，建立来源、原料档位、完整级配、沥青产品标记、试验组、试件和性能结果之间的关系。按企业说明识别沥青系列，同时保留“方案一、方案二、自制、调和、改性”等原始标记，不合并同标号不同配方。油石比换算、级配权重、合成筛孔通过率及新加油石比等可复算字段由公式核查。对疑似汇总行、跨组公式、属性列复制、来源别名和缺失字段，保存原值、位置、处理依据与证据状态；重算候选不覆盖原始数据。缺少的成本、施工条件、改性剂或助剂信息不推断为零或未添加。

场景规则覆盖高温重载车辙处治、低温抗裂和水损害修复，描述工法、结构层位、交通与病害条件、关注性能、要求来源和优先级。企业工作簿参考值与团队构造的演示阈值分别登记；演示阈值不作为规范条款。信息不完整时提示补充或转人工确认，工程师调整要求后保留修改前后值与原因。

## 3.3 候选筛选与性能预测
系统先从企业历史方案中检索候选，按材料身份、来源、完整级配、RAP比例、油石比和可用性能筛选，再执行组成、级配、适用条件与已知性能要求检查。状态分为满足、不满足、缺测和不可比。证据不全的方案可作为待验证对象展示，但不自动判为工程可行。候选卡展示关键性能、组分、证据来源及差异；工程师可调整性能优先级，查看方案排序与权衡变化。

配方研究模块已生成1,098个计算候选，用于展示候选空间和人机协同调整；通过设计距离与观测曲线范围检查不代表性能合格或已完成实验验证。自动配方优化尚未作为工程放行功能启用。模型优先使用设计阶段已知的筛分曲线、材料比例、RAP比例、油石比和明确配方标记，不将设计后测得的目标指标作为默认输入。各性能分别建模，按实验组与来源代理组划分训练和测试，避免同配方平行试件或重复原料曲线造成泄漏。模型与均值基线在相同划分下比较，只有在统一验证中显示稳定收益后，才提高其在推荐中的权重。

## 3.4 案例与交付
原型以高温重载、低温抗裂、水损害、较高RAP比例和组合约束五个案例展示流程。每案明确场景与约束、候选范围、推荐依据、关键指标、未知条件和对照方法。构造案例用于验证软件逻辑，不作为真实工程效果或行业收益证据。交付包括可运行原型、场景与材料结构化数据、规则说明、接口契约、数据复核记录、案例报告和复现说明。后续取得独立实验数据后，可开展盲测并深化模型更新、主动试验选择与企业系统集成。

# 四、应用前景分析

系统可优先服务于企业材料研发人员、配合比设计人员和道路养护方案比选人员，用于查找历史方案、核对材料组成、比较多项性能、解释候选冲突并形成可追溯记录。结构化数据和规则有助于积累可复用的研发知识；统一的场景—材料流程可辅助工程师开展方案比选。当前可展示的价值是数据关联、规则检查、候选比较、证据追溯与方案调整。实际设计时间、工程推荐成功率、成本、寿命和碳排放改善仍需通过真实用户任务、独立材料试验及可靠的成本和生命周期数据验证。
