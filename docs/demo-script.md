## 答辩结构

1. 用户与场景：工程师怎样从养护病害和材料库存形成可复核方案。
2. 数据证据：原表口径、跨表身份、缺失与疑似汇总如何处理。
3. 系统闭环：场景输入、硬约束初筛、依据追溯、微调失效、审核回流、冻结报告。
4. 五案例：覆盖高温、低温、水损害，并展示高RAP与空候选。
5. 算法结果：嵌套分组基准、实际有效组数、真实负结果与区间假设。
6. 价值与下一步：减少手工查表和混淆证据；等待企业字段确认与独立试验，不虚构成本或寿命收益。

## 常见问题

“为什么模型没有高精度？” 当前只有72至85个各指标有效操作配方标签，35至37个阻断分组，关键试验条件与料源身份不完整。严格分组后没有稳定泛化改进，系统据此保留历史初筛与研究预测。

“建议复核是不是工程达标？” 它只代表当前数值目标与历史聚合记录的匹配，仍需要项目适用性审核和相应试验。

“为什么不直接优化RAP和新加沥青？” RAP比例质量基准与旧沥青有效性尚未确认，自动生成精确配方会混淆口径。当前可保留微调假设并安排验证。

“试验查询次数是否减少？” 固定历史小池回放在C1中瓶颈启发式用了3次，而ID基线1次；不能声称效率提升。保存真实揭示序列供进一步改进。

“是否已经企业验证？” 尚未获得外部评议或独立实测；问题清单与验证方案已准备，结果取得后单独归档。

## 故障处理

端口被占用时用`start-local.ps1 -Port 8767`。模型失效或缺失时继续使用历史选材，不把错误替换成虚构预测。界面无法运行时，打开已导出的HTML报告与案例截图；数据库恢复应从备份复制到新文件，再用ASPHALT_DATABASE指向恢复副本，保留原文件。
