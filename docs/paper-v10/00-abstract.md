# 摘要

道路养护方案确定后，工程师还要把路段的气候、荷载和病害要求落实到具体材料。历史试验表格能够提供性能数值，却常常缺少与项目要求一起使用的判断过程：阈值从何而来，几个合格候选之间怎样取舍，调整要求或配方后哪些结论需要重新计算。数智选材围绕这段工作设计材料推荐与协同设计系统，将需求确认、历史候选比较和配方探索组织为连续的操作过程。

系统以带来源的性能要求作为输入，先逐项检查硬约束，再对数值可行候选计算非支配关系，并按工程师选择的指标优先顺序比较。要求变更、偏好切换和配方调整分别生成相应记录，保留前一步的需求与选择理由。面对空结果，系统根据候选的已知失败和缺测情况，给出资料补充方向；在数值完整的有限候选范围内，进一步计算最小冲突及删除见证。配方探索从准确的历史父配方展开，草案保存组成变化、原需求和设计意图。

作品基于企业工作簿建立180个历史操作键，以84条AC-13记录开展五个构造案例。五案与同池全约束查表基准的数值可行数均为2、2、5、1、0。水损害案例中的五个候选全部非支配，切换偏好后，优先查看的材料由H变为K；寒冷案例保留应变并列事实，并将油石比4.9%至5.0%的探索保存为设计草案。复合要求案例区分84条目录的证据不足状态与35条完整数值子池中的四组最小冲突。已有计算研究还比较了四项性能模型，并形成1098个局部配方假设，为后续模型与候选生成设计提供依据。

系统采用React、FastAPI和SQLite实现，交付结构化数据、接口、案例记录和可运行原型。作品的应用价值集中在要求追溯、多性能取舍和设计交接：工程师能够解释一次选择，也能够在条件改变后沿着原有依据继续工作。

关键词：道路养护；材料推荐；多目标取舍；人机协同；数据溯源
